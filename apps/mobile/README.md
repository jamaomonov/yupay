# @yupay/mobile

The YuPay iOS and Android app: Expo SDK 57, expo-router, TanStack Query. Why Expo and why in
the monorepo: [ADR-0100](../../docs/decisions/0100-native-mobile-app-with-expo.md).

## Run it

```bash
make dev-mobile          # or: pnpm --filter @yupay/mobile start
```

Scan the QR code with **Expo Go** (App Store / Google Play) on a phone in the same Wi-Fi. The
app talks to production (`https://api.yupay.uz`) unless `EXPO_PUBLIC_API_URL` says otherwise.

`w` in the dev server opens the web preview. A browser blocks `api.yupay.uz` from `localhost`
(CORS — a phone has no such rule), so the preview needs `EXPO_PUBLIC_API_URL` pointed at the
local API or at a CORS-adding proxy.

## Layout

| Path                    | What                                                     |
| ----------------------- | -------------------------------------------------------- |
| `src/app/(tabs)/`       | The four tabs: home, catalog, orders, profile            |
| `src/app/brand/[slug]`  | A game: products, player ID with the live check, amount  |
| `src/app/sign-in`       | The front door: Telegram, Google, Steam, email, password |
| `src/app/checkout`      | Checkout as the account: Payme / Click / Uzum, pay       |
| `src/app/order/[id]`    | One order's status, asked every 3 s until it settles     |
| `src/app/account`       | The account and sign-out; `promo`, `choose` from profile |
| `src/app/wallet`        | Balance, «top up», history; `topup` starts a deposit     |
| `src/app/notifications` | Opened by the home bell; empty until push lands          |
| `src/components/`       | `ui.tsx` (text, card, button, chip) and screen pieces    |
| `src/theme/tokens.ts`   | Light and dark palettes, fonts, radii                    |
| `src/lib/api.ts`        | API calls through `@yupay/api-client`                    |
| `src/lib/orders.ts`     | `POST /orders`, payment intent, order reads              |
| `src/lib/checkout.ts`   | Checkout rules without network (unit-tested)             |
| `src/lib/wallet.ts`     | Top-up bounds, history rows, «from balance» (tested)     |
| `src/lib/session.tsx`   | Access token in memory, refresh token in the keychain    |
| `src/lib/i18n.tsx`      | Strings from `packages/i18n/locales/*/mobile.json`       |

## Launch and sign-in

The native splash hands over to `components/Launch.tsx` (same colours, the mark in the same
place) while the stored session is restored. Then `app/_layout.tsx` decides with
`Stack.Protected`: without an account only the sign-in screen exists, and signing in or out
switches the whole stack. An offline restore does not sign anyone out — the launch screen
offers «retry» and the stored token stays. There is no guest checkout in the app.

## Checkout

`POST /orders` as the account, with no email field — receipts follow the account (sent with `X-Yupay-Surface: mobile`, recorded as
`orders.source = mobile`), then `POST /payments/intents`. The acquirer's page opens in the
in-app browser (an app link such as Uzum's leaves the app); when the buyer comes back, the
order screen asks for the status. The return URL is the storefront's order page, the only
origin the API accepts.

## Design rules

The 2026-10-22 audit (rules: 4-pt grid, 44-pt touch targets, WCAG AA in both themes) set
these; keep new screens on them.

- **Type**: `T` variants only — `display` 26 (Unbounded, tab titles and balances), `title`
  20, `amount` 17 (prices, tabular), `body`/`h2` 15, `label`/`small` 13. Inter 500 and 600.
- **Spacing**: multiples of 4 (`space` in `theme/tokens.ts`); the side gutter is 16.
- **Touch**: anything tappable is at least `TOUCH` (44) — size it or give it `hitSlop`.
- **Colour**: `dim` is for placeholders and chevrons, never for text that must be read.
  Disabled buttons are grey, not faded lime. Light-theme cards carry `cardShadow`.
- **States**: loading is a `Skeleton` in the content's shape (they breathe on one shared
  pulse); an order's status is a `Badge` in `stageTone`'s colour; an empty screen shows
  `EmptyArt` with its own icon.
- **Motion**: a tab's content and list rows arrive through `FadeIn` (rows staggered); the brand
  logo springs in on its page; the delivered mark pops with a success haptic. React Native's
  `Animated` only — the React Compiler lint refuses refs read during render, so values live in
  `useState(() => new Animated.Value(…))`.
- **Text size**: the phone's setting is followed, capped by `maxFontSizeMultiplier` (1.4 text,
  1.3 buttons and chips, 1.2 inputs, tab labels and `display`); buttons, chips and badges take
  `minHeight`, never a fixed height.
- **Dark theme**: graphite-navy (`#11141F` / cards `#1A1E2D`), not near-black.
- **Covers**: a game with no hero image gets its own logo blurred as a cover; with no logo
  either, a gradient picked by the slug.
- **Icon**: `assets/images/icon.png` (opaque, App Store), `icon-dark.png` and
  `icon-tinted.png` for iOS 18's appearances, and the three Android adaptive layers — all
  rendered from one SVG of the mark.

## Remembered player ID

A brand page fills in the ID (and server) the game was last bought for
(`lib/player-memory.ts`, SecureStore `player.<slug>`); what the buyer types wins. It is saved
when they go to checkout and never leaves the phone.

## Pull to refresh

Home, catalogue, orders, profile and the balance refresh on a pull: `Screen`'s `onRefresh`.

## Typed amounts

Steam is bought in dollars and Telegram Stars by count, so their pages show a field instead of
tiles (`lib/amount.ts`, `components/brand/AmountField.tsx`). The bounds come from the SKU:
`min_amount_usd`/`max_amount_usd` (whole dollars, rounded inward) or `min_qty`/`max_qty`. The
price shown is the typed amount × `display_price`, rounded to whole soʻm as the API rounds a
total. The order line carries `amount_usd` for dollars and `qty` for units.

## Balance

The profile's balance card opens `wallet`: the spendable `user_wallet` balance, «top up», and the
last 50 movements (the buyer's own leg of each ledger entry, signed in their favour; an order
payment opens that order). `topup` posts `POST /wallet/topup` with one `Idempotency-Key` per
amount and method, opens the acquirer, and reads the balance again when the buyer comes back —
it moves once the acquirer settles. Bounds are the website's: 5 000 – 5 000 000 soʻm. At
checkout «from balance» comes first and is picked when the balance covers the order (provider
`wallet`, settles at once, no page to open); when it does not, it says how much is missing and
links to `topup`.

## Sign-in

Email and password for now. The app asks the API for both tokens in the JSON
(`X-Yupay-Token-Transport: body`, ADR-0101), keeps the refresh token in SecureStore and the
15-minute access token in memory, and refreshes with the token in the body; a 401 refreshes
once and retries. Registration (sent with `X-Yupay-Surface: mobile`, so the account records
`signup_source = mobile`) sends the confirmation email; the link opens the website, and the
buyer then signs in here. «Forgot password» opens the website's page.

Telegram, Google and Steam go through the storefront's `/app-auth` page in the system browser,
which returns the provider's answer to `yupay://auth` (ADR-0101). In Expo Go the return address is
`exp://<LAN IP>:8081/--/auth`, which the page also accepts. Google needs
`https://yupay.uz/app-auth` among the web OAuth client's redirect URIs.
