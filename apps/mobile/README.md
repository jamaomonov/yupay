# @yupay/mobile

The YuPay iOS and Android app: Expo SDK 57, expo-router, TanStack Query. Why Expo and why in
the monorepo: [ADR-0100](../../docs/decisions/0100-native-mobile-app-with-expo.md).

## Run it

```bash
make dev-mobile          # or: pnpm --filter @yupay/mobile start
```

Scan the QR code with **Expo Go** (App Store / Google Play) on a phone in the same Wi-Fi. The
app talks to production (`https://api.yupay.uz`) unless `EXPO_PUBLIC_API_URL` says otherwise.

`w` in the dev server opens the web preview. A browser blocks `api.yupay.uz` from `localhost`
(CORS — a phone has no such rule), so the preview needs `EXPO_PUBLIC_API_URL` pointed at the
local API or at a CORS-adding proxy.

## Layout

| Path                   | What                                                    |
| ---------------------- | ------------------------------------------------------- |
| `src/app/(tabs)/`      | The four tabs: home, catalog, orders, profile           |
| `src/app/brand/[slug]` | A game: products, player ID with the live check, amount |
| `src/app/checkout`     | Guest checkout: email, Payme / Click / Uzum, pay        |
| `src/app/order/[id]`   | One order's status, asked every 3 s until it settles    |
| `src/app/sign-in`      | Email and password: sign in, or register                |
| `src/components/`      | `ui.tsx` (text, card, button, chip) and screen pieces   |
| `src/theme/tokens.ts`  | Light and dark palettes, fonts, radii                   |
| `src/lib/api.ts`       | API calls through `@yupay/api-client`                   |
| `src/lib/orders.ts`    | Guest token, `POST /orders`, payment intent, order read |
| `src/lib/checkout.ts`  | Checkout rules without network (unit-tested)            |
| `src/lib/session.tsx`  | Access token in memory, refresh token in the keychain   |
| `src/lib/i18n.tsx`     | Strings from `packages/i18n/locales/*/mobile.json`      |

`ios/` and `android/` are generated by EAS at build time and never committed.

## Checkout

A guest order, as on the website: the email gets a guest token, `POST /orders` (sent with
`X-Yupay-Surface: mobile`, recorded as `orders.source = mobile`), then `POST /payments/intents`.
The acquirer's page opens in the in-app browser (an app link such as Uzum's leaves the app);
when the buyer comes back, the order screen asks for the status. The return URL is the
storefront's order page, the only origin the API accepts. Orders and the last email are kept
on the phone in SecureStore (`src/lib/guest-orders.ts`), up to twelve.

## Sign-in

Email and password for now. The app asks the API for both tokens in the JSON
(`X-Yupay-Token-Transport: body`, ADR-0101), keeps the refresh token in SecureStore and the
15-minute access token in memory, and refreshes with the token in the body; a 401 refreshes
once and retries. Registration sends the confirmation email; the link opens the website, and
the buyer then signs in here. «Forgot password» opens the website's page. Signed in, checkout
places the order as the account (the email becomes the receipt address and may be blank) and
the orders tab lists the account's orders, with this phone's guest orders under them.

Telegram and Google go through the storefront's `/app-auth` page in the system browser, which
returns the provider's answer to `yupay://auth` (ADR-0101). In Expo Go the return address is
`exp://<LAN IP>:8081/--/auth`, which the page also accepts. Google needs
`https://yupay.uz/app-auth` among the web OAuth client's redirect URIs.
