# `promo` — промокоды

Фиксированные подарочные коды: админ выпускает, покупатель активирует, деньги
падают **сразу в `user_wallet`** (`D user_wallet / C house_promo_expense`,
`kind="promo.redeem"`) — видны в балансе и тратятся через wallet-шлюз без
дополнительной механики. См. ADR-0029: вариант с начислением в
`user_promo_credit` отвергнут, потому что этот счёт не участвует в оплате и
скрыт в UI.

## Таблицы

| Таблица             | Назначение                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `promo_codes`       | Код (UPPERCASE, UNIQUE), номинал+валюта, `max_redemptions` (NULL = безлимит), `expires_at`, `active`, `created_by` |
| `promo_redemptions` | Кто что активировал. `UNIQUE(promo_code_id, user_id)` — раз на пользователя; ссылка на ledger-транзакцию           |

## Инварианты

- **Одна активация на пользователя** — гарантируется UNIQUE-констрейнтом
  (вставка под SAVEPOINT, конфликт → 409).
- **Глобальный лимит не обгоняется гонкой** — строка кода берётся
  `FOR UPDATE`, конкурирующие активации сериализуются.
- **Ровно одна ledger-проводка** на пару (код, пользователь): ключ
  `promo:{code_id}:{user_id}` в `wallet.post`.
- **Idempotency-Key** обязателен; повтор с тем же ключом реплеит исходный
  успех (ключ хранится на redemption-строке), новый ключ → 409.

## HTTP

```
POST /api/v1/promo/redeem                      — активировать (Bearer, Idempotency-Key)
POST /api/v1/admin/promo                       — выпустить код (код опционален — сгенерируем)
GET  /api/v1/admin/promo                       — список с количеством активаций
POST /api/v1/admin/promo/{id}/deactivate       — выключить код
```

### Коды отказа

Одного статуса мало: 409 покрывает четыре разные причины, и клиенту нужно
показать точную. Поэтому каждый отказ несёт машиночитаемый `code` — член
problem+json рядом с англоязычным `detail`. **Ветвиться нужно по `code`**,
`detail` — для логов, не для пользователя.

| Статус | `code`           | Когда                                    |
| ------ | ---------------- | ---------------------------------------- |
| 404    | —                | кода не существует                       |
| 409    | `already_redeemed` | этот пользователь уже активировал код   |
| 409    | `inactive`       | код выключен админом                     |
| 409    | `expired`        | вышел `expires_at`                       |
| 409    | `exhausted`      | выбран глобальный `max_redemptions`      |
| 409    | `duplicate_code` | (админ) такой код уже существует         |

Незнакомый `code` клиент обязан схлопывать в общую формулировку, а не
показывать сырое значение — см. `apps/miniapp/src/lib/promo.ts`.

## Что дальше

- Реферальные коды (`created_by=user`, выплата рефереру) — отдельный kind
  поверх той же пары таблиц.
- Процентные скидки на заказ — другая механика (модификатор цены, не
  wallet-кредит), сюда не тащить.
